# 사이 Next.js 프론트엔드

Next.js App Router, TypeScript, SCSS, Zustand 기반 PWA입니다. 백엔드는 형제 폴더 [`backend`](../backend/README.md)의 NestJS 서버입니다.

## 실행

백엔드를 먼저 실행합니다. 테스트는 백엔드에서 `pnpm start:test`(4100번), 이 폴더에서 `pnpm dev`(3001번)로 실행합니다. 개발 프론트엔드의 API 요청은 테스트 DB로 연결됩니다. 운영은 백엔드에서 `pnpm start`(4000번), 이 폴더에서 `pnpm build` 후 `pnpm start`(3000번)로 실행합니다. 운영 프론트엔드는 운영 DB로 연결됩니다. 개발 빌드 `.next-dev`와 운영 빌드 `.next`는 분리되어 동시에 실행할 수 있습니다. `pnpm typecheck`와 `pnpm build`로 프론트엔드를 검사합니다.

앞으로 기능 개발과 확인은 테스트 환경(3001/4100, `E:\테스트 서버`)에서만 진행합니다. 운영 서버 실행·운영 DB 변경은 사용자가 명시적으로 요청할 때만 합니다.

## 화면과 데이터

- `/start`, `/signup`, `/login`, `/change-password`, `/pending`: 시작, 가입 요청, 재로그인, 임시 비밀번호 변경, 승인 대기·상태 확인
- `/community/home`, `/community/word`, `/community/photos`, `/community/prayer`, `/community/me`: 승인 회원 공동체
- `/community/photos/[id]`: 사진 상세, 좋아요, 댓글, 내 댓글 수정·삭제
- `/admin/members`, `/admin/approvals`, `/admin/reports`, `/admin/people`, `/admin/settings`: 운영 대시보드와 관리 화면

회원·게시물·사진·댓글·기도·신고·공지·운영 설정은 서버 API를 사용합니다. Zustand에는 화면 이동 상태만 `sai-church-ui-v2` 키로 저장합니다. 이전 데모 데이터는 브라우저의 `sai-church-demo` 키에 남지만 서버 DB로 자동 전송·이전하지 않습니다. 기존 데모 사진이나 글이 필요하면 별도 이전 절차가 필요합니다.

오늘의 말씀과 질문은 한국 시간 날짜별 30일 순환표에서 표시되고, 운영자가 지정한 날짜에는 직접 저장한 내용이 우선합니다. 열린 홈·말씀 화면은 자정 또는 앱 재활성화 시 새 날짜를 확인합니다. 사용자가 과거 날짜를 보고 있으면 그 선택은 유지합니다. 말씀 카드의 링크는 해당 장의 대한성서공회 성경플랫폼을 새 탭으로 엽니다.

승인 전에는 화면을 둘러볼 수 있지만 작성·반응 등은 서버가 차단합니다. 신규 회원은 가입할 때 12자 이상 비밀번호를 정하고, 세션이 만료되면 전화번호와 비밀번호로 다시 로그인합니다. 이전에 가입해 비밀번호가 없는 회원은 기존 세션으로 내 공간에서 설정하거나, 세션이 없으면 주 운영자에게 임시 비밀번호 발급을 요청합니다. 임시 비밀번호로 로그인하면 `/change-password`에서 현재 임시 비밀번호와 새 비밀번호(12~128자)를 입력해야 공동체를 이용할 수 있습니다. 기존 비밀번호가 있는 회원도 내 공간에서 이 화면으로 이동해 변경할 수 있습니다. 운영자는 별도 로그인 화면을 사용합니다. 운영 설정의 기본정보·운영자 계정·공지사항은 API에 연결되어 있습니다.

이 버전은 로컬 서버 확인용입니다. 외부 사용자에게 제공하려면 HTTPS 공개 주소와 PC 상시 실행 구성이 필요합니다.
